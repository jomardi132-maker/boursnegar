# پروتکل حافظه زنده پروژه

این سند قرارداد عملیاتی ثبت وضعیت بورس‌نگار است. هدف آن این است که اجرای بعدی از روی شواهد ادامه دهد، نه از روی حدس یا خلاصه‌های قدیمی.

## قبل از هر اجرای مهم

1. `CURRENT_STATE.md` را بخوان.
2. فایل‌های مرتبط در حافظه محلی Codex را جست‌وجو کن.
3. وضعیت واقعی Git، release فعال، PM2، data service، backup و health را دوباره بررسی کن.
4. تفاوت بین داده‌ی محلی، ledger Production، snapshot تحلیلی و UI رندرشده را جدا نگه دار.

## بعد از هر تغییر یا ممیزی

1. شواهد قطعی را در `CURRENT_STATE.md` با تاریخ UTC ثبت کن.
2. یک یادداشت کوچک و append-only در `/home/king/.codex/memories/extensions/ad_hoc/notes/` با نام `<timestamp>-<slug>.md` بساز.
3. در یادداشت، علت ریشه‌ای، اعداد واقعی، checksum یا backup، نتیجه تست، release و گیت‌های باقی‌مانده را بنویس.
4. داده‌ی فاقد منبع، هویت ناشناخته، پوشش ناکافی و نتیجه‌ی احرازنشده را صریحاً ثبت کن؛ آن‌ها را با fallback یا عدد ساختگی پنهان نکن.
5. اگر Production تغییر کرده، مسیر rollback و آخرین health check را ثبت کن.

## قالب حداقلی یادداشت

```text
# <موضوع>

تاریخ و محدوده:
علت یا یافته:
شواهد و checksum/backup:
تغییر انجام‌شده:
تست و Production proof:
گیت‌های باقی‌مانده:
قاعده ادامه کار:
```

این پروتکل مکمل حافظه محلی Codex است؛ فایل‌های حافظه را مستقیماً بازنویسی نکن و فقط یادداشت جدید append-only اضافه کن.
